## yt-dlp JS runtime

Test video: `https://www.youtube.com/watch?v=jNQXAC9IVRw` ("Me at the zoo"). No bot check or sign-in prompt; no second video needed. yt-dlp 2026.10.26.

Working command (verified, all `rc=0`, 25 formats incl. audio-only 233/234/139/249/250):

```
uvx --quiet --with deno "yt-dlp[default]@latest" -J --no-playlist "https://www.youtube.com/watch?v=jNQXAC9IVRw"
```

| OS | Result |
|---|---|
| macOS (local) | OK. Run with node removed from PATH. stderr has only an ffmpeg warning, no JS-runtime warning. |
| Linux (docker `ghcr.io/astral-sh/uv:python3.12-bookworm-slim`, no node/deno) | OK, same stderr (ffmpeg warning only), 25 formats. |
| Windows | NOT CHECKED, deferred to CI (no workflow created per controller ruling). |

Control run on macOS without `--with deno` and no node in PATH: stderr shows `WARNING: [youtube] No supported JavaScript runtime could be found. Only deno is enabled by default ...`. So the `deno` PyPI package is what removes the warning; it is not a false pass. The `"yt-dlp[default,deno]@latest"` fallback was not needed and not tried.

Notes: the URL must be quoted in zsh (`?`). The only stderr warning is `ffmpeg not found`; the tool needs ffmpeg (or a decoder) for audio extraction, which is for Task 5 to handle.
